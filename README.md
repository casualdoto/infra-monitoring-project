# Infra Monitoring Project

Учебный DevOps-проект: мониторинг доступности API, анализ логов и сетевого
трафика, контейнеризация echo-сервиса с Nginx и проверки GitHub Actions.

## Git Workflow

[Публичный репозиторий](https://github.com/casualdoto/infra-monitoring-project).

- `main` — защищённая основная ветка, изменения через Pull Request.
- `feature/monitoring` — рабочая ветка; вся дальнейшая работа ведётся в ней.
- Защита `main` действует и для администратора: требуется PR и разрешение
  обсуждений, force push и удаление запрещены. Обязательные одобрения
  не включены, чтобы автор мог самостоятельно завершить учебный проект.
- Итоговый PR из `feature/monitoring` в `main` создаётся после остальных этапов.

## Передача проекта на удалённый сервер через SSH/SCP

Ниже приведён пример передачи проекта с локальной Ubuntu
на удалённый сервер Ubuntu.

Перед выполнением команд необходимо:

- Подготовить сервер с доступным SSH-сервисом.
- Создать на сервере пользователя с именем deploy.
- Установить на сервер Docker Engine и Docker Compose.
- Предоставить пользователю deploy возможность выполнять sudo.
- Заменить server.example.com на фактический адрес сервера.

Адрес server.example.com и пользователь deploy в примерах
являются условными.

Команды с пометкой «локальная машина» выполняются на компьютере,
с которого передаётся проект. Команды с пометкой «сервер»
выполняются после подключения по SSH.

### Генерация SSH-ключа

На локальной машине установите SSH-клиент:

```bash
sudo apt update
sudo apt install -y openssh-client
```

Создайте отдельный ключ для деплоя:

```bash
ssh-keygen -t ed25519 \
  -f ~/.ssh/infra_monitoring_ed25519 \
  -C "infra-monitoring-deploy"
```

При запросе задайте парольную фразу для защиты приватного ключа.
Если файл ключа уже существует, не перезаписывайте его:
используйте существующий ключ или выберите другое имя.

Будут созданы:

- ~/.ssh/infra_monitoring_ed25519 — приватный ключ.
- ~/.ssh/infra_monitoring_ed25519.pub — публичный ключ.

Приватный ключ остаётся на локальной машине.
Его нельзя добавлять в Git, передавать на сервер или включать в отчёт.
На сервер копируется только публичный ключ.

### Копирование публичного ключа

На локальной машине выполните:

```bash
ssh-copy-id -i ~/.ssh/infra_monitoring_ed25519.pub \
  deploy@server.example.com
```

Для первичной установки ключа нужен доступ к серверу,
например по паролю пользователя deploy.

При первом подключении SSH показывает отпечаток ключа сервера.
Перед подтверждением сравните его со значением, полученным
через доверенный канал: консоль сервера или его администратора.

После установки публичного ключа проверьте подключение:

```bash
ssh -i ~/.ssh/infra_monitoring_ed25519 deploy@server.example.com
```

Если ключ защищён парольной фразой, SSH может запросить её.
Это парольная фраза локального ключа, а не пароль пользователя сервера.

Чтобы завершить сеанс:

```bash
exit
```

### Создание и передача архива

На локальной машине перейдите в проект:

```bash
cd ~/projects/infra-monitoring-project
git switch feature/monitoring
git status
```

Перед упаковкой убедитесь, что все необходимые изменения
закоммичены. Команда git archive включает только файлы из коммита HEAD.

Создайте архив за пределами рабочей папки:

```bash
git archive \
  --format=tar.gz \
  --prefix=infra-monitoring-project/ \
  --output=/tmp/infra-monitoring-project.tar.gz \
  HEAD
```

Проверьте содержимое:

```bash
tar -tzf /tmp/infra-monitoring-project.tar.gz
```

Передайте архив на сервер:

```bash
scp -i ~/.ssh/infra_monitoring_ed25519 \
  /tmp/infra-monitoring-project.tar.gz \
  deploy@server.example.com:
```

Архив будет сохранён в домашней папке пользователя deploy.
Передача выполняется через защищённое SSH-соединение.

## Пример деплоя на сервер

Предполагается, что Docker Engine и Docker Compose уже установлены,
а архив передан в домашнюю папку пользователя deploy.

С локальной машины подключитесь к серверу:

```bash
ssh -i ~/.ssh/infra_monitoring_ed25519 deploy@server.example.com
```

Следующие команды выполняются на сервере.

Создайте папку для приложения и распакуйте архив:

```bash
mkdir -p ~/apps

tar -xzf ~/infra-monitoring-project.tar.gz \
  -C ~/apps

cd ~/apps/infra-monitoring-project
```

Проверьте Compose-конфигурацию:

```bash
sudo docker compose config --quiet
```

Скачайте образы и запустите сервисы:

```bash
sudo docker compose pull
sudo docker compose up -d
```

Проверьте состояние контейнеров:

```bash
sudo docker compose ps
```

Проверьте конфигурацию Nginx:

```bash
sudo docker compose exec proxy nginx -t
```

Выполните запрос:

```bash
curl -i http://localhost:80
```

Ожидается HTTP 200 и текст:

```text
Monitoring Service Active
```

Проверьте доступность скриптом мониторинга:

```bash
./check_api.sh http://localhost:80
echo "Код завершения: $?"
```

Ожидается сообщение «API доступен» и код завершения 0.

Для просмотра логов:

```bash
sudo docker compose logs --tail=50 api proxy
```

Для остановки и удаления контейнеров стека:

```bash
sudo docker compose down
```

В текущей конфигурации порт Nginx опубликован на 127.0.0.1 сервера.
Поэтому проверка curl выполняется на самом сервере через SSH.
Прямой доступ по публичному IP сервера этой конфигурацией не предусмотрен.
